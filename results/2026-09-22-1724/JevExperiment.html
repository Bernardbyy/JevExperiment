What is Jev?

LLMs are optimized for human readability. Jev is optimized for software decisions.

Illustration: youtube.com/shorts/HTbm-6VFMUk

General-purpose LLM

Optimized for chatting with humans, writing token after token. Can reason, but at higher cost and latency.

e.g. drafting a reply to an unhappy customer

Jev — a decision model

Answers a question with fixed answer options, plus how confident it is.

Jev's three primitives:

  • Noul: True / False (e.g. should the chatbot answer this message?)
  • Choice: Pick one from a fixed list of options (e.g. Payment & Billing / Product Question / Prompt Injection, etc.)
  • Rate: A score on a scale you define (e.g. on a scale of 1–5, how annoyed is the customer?)

How we tested it

We picked one everyday decision and put four models through it

The decision: an input guardrail — should a support chatbot answer this message? Chosen because:

  • It runs on every single message, so a slow guardrail delays every reply
  • It's paid per message, so a small price difference becomes a large bill at volume

We measured:

  • Accuracy: how often each model was right to reject prohibited queries
  • Latency: how fast it answered
  • Cost: what each answer cost

Test case

Input guardrail: 100 mock customer messages to allow or block

The guardrail must block:

  • Irrelevant queries — off-topic chat
  • Data extraction — other people's data
  • Prompt injections — overriding the bot's rules
  • Threats and abuse — aimed at staff
  • Out of scope — things the shop doesn't sell
  • For this experiment, we generated and manually verified a mock dataset of 100 messages, written the way Malaysian customers write — 50 the bot should answer, 50 it should refuse
  • 10 categories of message, 10 of each. Example: Order Status, Prompt Injection, Off Topic, etc.
  • Each model gave two answers per message: Allow / Block, and which category the message belongs to

Full dataset: github.com/Bernardbyy/JevExperiment/blob/main/guardrail.csv

The takeaway: for quick, structured, high-volume decisions, a decision model is worth testing before reaching for an LLM — here it was as accurate, faster and far cheaper. LLMs remain the tool for work that needs reasoning or writing.

A2 · How we measured

Same instructions, same route, default settings for every model

  • Accuracy — % of messages where the model's answer matched our label. Scored separately for Allow/Block and for category
  • Latency — how long the model took to answer, as recorded by OpenRouter. P50 = median, P90 = slowest 10%
  • Cost — billed by OpenRouter for every call, at each provider's list price, no markup
  • All four models called through OpenRouter, on each provider's standard tier
  • Identical wording — Jev receives it as typed questions, the others as instructions plus a strict answer format; a check confirms both carry the same text
  • Default parameters — every model at its vendor's default settings

A3 · Jev's cut-off

Jev gives a probability, not a verdict — we choose the cut-off

Jev returns how likely a message is safe to answer. We allow it at 80% or above, block below.

The 80% cut-off was chosen on half the messages and confirmed on the other half. A higher cut-off blocks more — safer, but refuses more real customers.

Jev's answers are produced independently, so its category and its allow/block call can disagree — it did on 3 of 100 messages.
